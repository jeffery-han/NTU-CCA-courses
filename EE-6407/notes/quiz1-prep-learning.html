Weeks 1–3 · Quiz 1 is closed book · 10% of the course

You cannot memorise a genetic algorithm. You can learn to run one.

Almost every mark in this quiz comes from executing a procedure correctly — counting queen conflicts, turning a fitness column into roulette probabilities, decoding a bit string, tracing a permutation crossover. This page makes you run each one until it is automatic, then tests you under time.

You have a computer science degree, so this page skips what you already own. P, NP, NP-complete, NP-hard, big-O, search trees — none of that gets re-taught. Module 1 covers only the handful of places where this course frames those ideas differently from a CS curriculum, which is exactly where marks get lost. Everything after that is genuinely new material.

Module 1

Fast lane: what your CS degree already gave you

0%Not started

After this module you can

  • Classify a problem with the course's y = M(x) framing, which is not standard CS vocabulary;
  • separate search space, feasible set and objective — the three words every later question quietly depends on;

1.1 The one framing that is new to you: y = M(x)

The course opens by classifying every problem through a single input–model–output relation. Read it as: a model \(M\) turns an input \(x\) into an output \(y\).

\[ y = M(x) \]

Read it aloud: "output equals model applied to input." Now cover up any one of the three and ask what kind of problem you are left with. That is the whole classification scheme.

UnknownKnownProblem typeYour CS name for it
\(x\)\(M\) and \(y\)Optimisation — find the input that produces the wanted outputSearch / constraint solving
\(M\)\(x\) and \(y\)Modelling / machine learning — find the rule that maps observed inputs to observed outputsSupervised learning, system identification
\(y\)\(x\) and \(M\)Simulation — run the model forwardJust… running the program
Why this is worth twenty seconds of memorising: it is the cheapest question the lecturer can set, it has appeared in past papers, and the answer is fully determined once you name which of the three letters is missing. Evolutionary algorithms live in the first row — they are optimisers.

1.2 Three words: search space, feasible set, objective

These are used loosely in CS conversation and precisely in this course. Keep them separate, because a later question will ask you to "state the search space" and will not accept a description of the objective.

SSearch space. Every candidate the encoding can express — including nonsense ones. If you encode a tour as a permutation of 9 cities, \(|S| = 9!\).
F ⊆ SFeasible set. The candidates that satisfy the hard constraints. Choosing an encoding where \(\mathcal F = S\) is a design win: every string is legal, nothing needs repair.
fObjective / fitness. The quality score. Say explicitly whether you are maximising or minimising — the marker looks for it.

Two problem types follow immediately:

  • CSP (constraint satisfaction problem): find any member of \(\mathcal F\). There is no objective — you either satisfy the constraints or you do not.
  • COP (combinatorial optimisation problem): find the best member of \(\mathcal F\) under \(f\).

The same real-world situation can be posed either way. "Place 8 queens with no attacks" is a CSP; "place 8 queens minimising the number of attacking pairs" is a COP whose optimum happens to solve the CSP. Evolutionary algorithms need a gradient of quality to climb, so we routinely convert a CSP into a COP by counting violations. That conversion is the single most reusable trick in the course.

1.3 Complexity: only the traps

You know this material. Here is the short list of places where it is answered wrongly in this course's scripts.

Trap 1 — NP does not stand for "non-polynomial." It is nondeterministic polynomial: a proposed yes-answer can be verified in polynomial time. Writing "non-polynomial" is treated as a conceptual error, not a slip of the pen, and it is the most commonly penalised sentence in past scripts.
Trap 2 — NP-hard need not be in NP. NP-hard means "at least as hard as everything in NP" under polynomial reduction. It says nothing about membership. The TSP optimisation problem ("find the shortest tour") is NP-hard but is not a decision problem at all, so it is not in NP, and therefore not NP-complete. The decision version ("is there a tour shorter than \(k\)?") is NP-complete.
Trap 3 — "NP-complete" is a conjunction, and you must say both halves. A problem is NP-complete when it is (a) in NP and (b) NP-hard. Half an answer earns half the marks.
Worked example 1 — correcting a flawed complexity claim

Claim to assess: "The travelling salesman problem is NP-complete, where NP means non-polynomial, so no algorithm can ever solve it."

Three separate errors:

  1. NP is nondeterministic polynomial, not non-polynomial.
  2. The TSP as usually stated — find the shortest tour — is an optimisation problem, hence NP-hard. Only its decision form is NP-complete.
  3. "No algorithm can ever solve it" is false. Exhaustive search solves it exactly; what is in doubt is solving it in polynomial time. And that is precisely the opening EAs walk through: give up the guarantee of optimality, keep the running time.

Model answer: "The decision version of TSP is NP-complete: it lies in NP because a proposed tour of length below \(k\) is verifiable in polynomial time, and it is NP-hard by reduction from Hamiltonian cycle. The optimisation version is NP-hard but not in NP. Exact algorithms exist but scale exponentially, which motivates heuristic search."

The bridge to the rest of the course. Exponential search spaces plus a verifiable-but-not-computable-fast optimum is exactly the situation where a metaheuristic earns its keep. Every remaining module is one answer to "what do you do when \(|S|\) is astronomically large and you cannot afford to be exact?"

Module 2

The evolutionary algorithm loop

0%Not started

After this module you can

  • Write the EA cycle in order, from memory, and say what each stage is for;
  • separate genotype from phenotype and say where decoding happens;
  • compute fitness-proportionate selection probabilities and explain what selection does not guarantee.

2.1 The idea in one sentence

Keep a population of candidate solutions; let the better ones have more children; make children by mixing and randomly perturbing parents; repeat. The population is the algorithm's memory, and the only problem-specific input is the fitness function.

The two natural inspirations, stated as the lecture does: Darwinian selection (fitter individuals reproduce more) and genetic inheritance with variation (children resemble parents but are not copies). Selection alone converges to a copy of the best thing you started with; variation alone is random search. You need both, and the exam likes you to say why.

2.2 The cycle, in order

Learn this as a ring, not a list — the last stage feeds the second.

1Initialise the population, usually at random, size \(\mu\). Random start = no bias towards any region.
2Evaluate each individual: decode genotype → phenotype, apply \(f\). This is the expensive step in real applications.
3Select parents — a stochastic bias towards higher fitness.
4Recombine (crossover): combine material from two parents.
5Mutate: perturb offspring slightly, at low probability.
6Evaluate offspring.
7Select survivors: decide who forms the next generation, from parents and offspring.
8Test termination. If not met, go back to stage 3.
Common mistake: putting mutation before crossover, or forgetting the second evaluation. Offspring must be re-evaluated before survivor selection — you cannot rank an individual whose fitness you never computed. Also note there are two distinct selection stages (parent and survivor); losing one costs a mark.

Termination criteria

Any of: a target fitness reached; a fixed budget of generations or evaluations exhausted; fitness improvement stalled for \(k\) generations (convergence); population diversity collapsed. Because an EA gives no optimality certificate, you must impose the stopping rule.

2.3 Genotype and phenotype

phenotypeThe solution as the problem sees it: a tour, a set of queen positions, a controller gain.
genotypeIts encoding — the string the operators actually manipulate.
geneOne position (locus) in the chromosome.
alleleA value that a gene can take. In binary the alleles are just 0 and 1.

Variation happens in genotype space; evaluation happens in phenotype space. Decoding is the bridge, and it runs before every fitness evaluation. Half the exam's calculation errors are decoding at the wrong moment — for example scoring the parents' fitness and reporting it as the children's.

2.4 Parent selection: the roulette wheel

Fitness-proportionate ("roulette wheel") selection gives individual \(i\) a slice of the wheel proportional to its fitness:

\[ p_i = \frac{f_i}{\sum_{j=1}^{\mu} f_j} \]

Read it aloud: "my share of the wheel is my fitness divided by everybody's fitness added up." Conditions of use: all \(f_i \ge 0\), and larger must mean better. If your objective is a cost to minimise, transform it first — otherwise the wheel rewards the worst solutions.

Lab 2

Roulette wheel simulator

Edit the fitness values and watch the probabilities and the wheel move. Then spin it repeatedly and see how often the worst individual still wins — this is the point about selection favouring rather than guaranteeing.

Selection pressure — and why you never just take the best

Selection pressure is how strongly the algorithm favours the fit. Turn it up too far — say, always breed only the single best individual — and every member of the population becomes a copy of it within a few generations. Diversity is gone, crossover has nothing left to combine, and the search freezes at whatever local optimum it found first. That failure has a name you must be able to produce: premature convergence.

Turn it down too far and the algorithm ignores quality and drifts as random search. The whole design problem is the balance.

Other selection schemes named in the course
  • Tournament selection: pick \(k\) individuals at random, breed the best of them. \(k\) tunes the pressure directly, and it needs no fitness sum — so it works with negative or minimised fitness.
  • Ranking (linear or exponential): sort the population and assign selection probability by rank rather than raw fitness. This cures the pathology where one individual with fitness 10 000 among values of 10 seizes the entire wheel.
  • Elitism (a survivor-selection policy): copy the best individual forward unchanged, so the best-so-far can never be lost to an unlucky generation.

Module 3

N-queens: the course's worked model

0%Not started

After this module you can

  • Explain why a permutation encoding beats the obvious ones, in terms of search-space size;
  • apply the diagonal conflict test \(|q_i - q_j| = |i - j|\) without double counting;
  • compute the fitness \(f = \binom{N}{2} - C\) and say which direction is better.

3.1 Why the encoding is the whole trick

Place \(N\) queens on an \(N \times N\) board so no two attack each other — along a row, a column or a diagonal. Compare three encodings for \(N = 8\):

EncodingSearch space \(|S|\)Constraints still to check
Any 8 squares of 64\(\binom{64}{8} \approx 4.4 \times 10^{9}\)rows, columns and diagonals
One queen per column, row free\(8^8 = 16\,777\,216\)rows and diagonals
Permutation of \(1..8\)\(8! = 40\,320\)diagonals only

The permutation \(q = (q_1, \ldots, q_N)\) reads: the queen in column \(i\) sits in row \(q_i\). Because it is a permutation, no row repeats and no column repeats — two of the three constraint families are satisfied by construction, and the search space shrinks by five orders of magnitude. This is the concrete payoff of "choose the representation first."

Say this in the exam: a good encoding makes infeasible solutions unrepresentable, so \(\mathcal F = S\) and no repair operator is needed. That single sentence answers a large family of representation questions.

3.2 The diagonal test

Two queens share a diagonal exactly when the row gap equals the column gap:

\[ |q_i - q_j| = |i - j| \qquad \text{for } i < j \]

Read it aloud: "if I moved as far sideways as I moved up or down, I travelled along a diagonal." Enforce \(i < j\) so each pair is tested exactly once.

Let \(C\) be the number of conflicting pairs. Since there are \(\binom{N}{2}\) pairs in total, define fitness as the number of non-attacking pairs:

\[ f(q) = \binom{N}{2} - C, \qquad \binom{N}{2} = \frac{N(N-1)}{2} \]

So bigger is better, the maximum is \(\binom{N}{2}\), and a perfect 8-queens solution scores \(28\). Note what this achieves: the CSP has become a COP with a smooth quality gradient the EA can climb.

Common mistake: counting each conflicting pair twice by looping over all ordered pairs, then reporting \(f = 28 - 2C\). Test unordered pairs only. For \(N = 8\) there are \(\binom{8}{2} = 28\) of them; for \(N = 4\), six.

3.3 Which operators are legal here?

This is where the representation bites back. A permutation genotype forbids most of the operators you would reach for by default:

  • One-point crossover fails. Cut \((1,2,3,4)\) and \((4,3,2,1)\) after position 2 and you get \((1,2,2,1)\) — two queens in row 2, none in rows 3 or 4. Not a permutation, not a legal board.
  • Bit-flip mutation is meaningless — the genes are not bits.
  • Swap mutation works: exchange two entries, and the result is still a permutation.

Module 6 develops the four crossovers that are legal on permutations. For now, hold on to the rule: the operators must suit the representation.

The two-stage search from the N-queens paper

The supplied IJCAT article adds an idea worth one sentence of recall: as \(N\) grows, solutions become denser in the permutation space, yet the space itself grows as \(N!\). The paper's method separates weak genes — queens involved in conflicts — from settled ones, and concentrates variation on the weak ones instead of perturbing the whole chromosome. It is a clean illustration of injecting domain knowledge into an operator, which is exactly what Module 7's no-free-lunch discussion says you must do.

This is the highest-value module in the page. A hand-worked SGA generation appears in the legacy quiz and across the past-paper walkthroughs, it carries the most marks per question, and it is pure procedure — which means it is fully winnable if you have done it five times. Do it five times.

4.1 The standing example

Note how brutally non-uniform the wheel already is: 1110 owns 63% of it on generation zero, purely because squaring exaggerates differences. That is selection pressure arriving through the fitness function, not through the selection scheme.

4.2 One generation, step by step

1Decode and evaluate. \(z = \sum_{k=0}^{L-1} 2^k b_k\), then \(f = z^2\). Sum the column: \(9 + 25 + 81 + 196 = 311\).
2Selection. Roulette draws produce a mating pool. Suppose the draws give [1110, 1001, 1110, 0101] — the strong string appears twice, the weakest is not selected at all.
3Pair and cross. Pair adjacent members and cross after bit 2:
\(11|10,\ 10|01 \longrightarrow 11|01 = \) 1101 and \(10|10 = \) 1010
\(11|10,\ 01|01 \longrightarrow 11|01 = \) 1101 and \(01|10 = \) 0110
4Mutate. Suppose one bit flips — the last bit of the fourth child: 0110 → 0111.
5Re-evaluate. New population [1101, 1010, 1101, 0111] decodes to \([13, 10, 13, 7]\), fitnesses \([169, 100, 169, 49]\).
6Report. Total fitness \(487\) (up from 311); best fitness \(169\) (up from 196 — down, in fact: read the caution below).
The subtlety that catches people: average fitness rose from \(311/4 = 77.75\) to \(487/4 = 121.75\), but the best individual fell from 196 to 169. Without elitism, a GA can and does lose its best solution. If a question asks "has the population improved?", answer on both statistics and name elitism as the fix.

Lab 4

Full SGA generation calculator

4.3 Three checks that cost you ten seconds and save you marks

  1. Probabilities sum to 1. If they do not, you divided by the wrong total — most often by the new generation's fitness sum instead of the current one.
  2. Length is preserved. Every child must have exactly \(L\) bits. Crossover never changes chromosome length.
  3. Re-decode after variation. Fitness of a child is computed from the child, never inherited from a parent.
State your assumptions in writing. Roulette outcomes and mutation events are sampled, not determined. If the question does not specify which strings were drawn, say "assume the draws give …" and proceed. A marker rewards a clearly stated assumption followed by correct arithmetic; an unexplained mating pool looks like a guess.
Worked example 3 — why f(x) = x² rather than f(x) = x

With \(f = x\), the same population scores \(3, 5, 9, 14\), summing to 31, giving probabilities \(0.097, 0.161, 0.290, 0.452\). With \(f = x^2\) the top string's share jumps from 45% to 63%.

The lesson: the fitness function is itself a tuning knob for selection pressure. Squaring, exponentiating, or otherwise stretching the objective sharpens the search and risks premature convergence; flattening it (for instance by ranking) slows convergence and preserves diversity. This is why ranking selection exists — it makes the pressure independent of how the objective happens to be scaled.

Module 5

Representations I — binary, integer, real-valued

0%Not started

After this module you can

  • Name the five representations and a problem suited to each;
  • decode a bit string onto a real interval and say what sets the resolution;
  • state why \(p_m\) is kept small, and compute expected flips and the probability of no flip;
  • give the allele-frequency argument for why mutation is indispensable;
  • show that arithmetic crossover cannot escape the parents' box, and that blend crossover can.

5.1 Representation is the first design decision

Everything downstream depends on it: the size and shape of \(S\), what counts as valid, how fitness is computed, and above all which variation operators are even legal. Memorise the lecture's rule verbatim — the operators must suit the representation.

5.2 Binary representation

Encoding maps the phenotype into \(\{0,1\}^L\); decoding is the inverse and runs before every evaluation. For unsigned integers:

\[ z = \sum_{k=0}^{L-1} 2^{k} b_k \]

and to place that on a real interval \([a, b]\):

\[ x = a + \frac{z}{2^{L} - 1}\,(b - a) \]

Read it aloud: "take how far along the integer range I am, as a fraction, and travel that same fraction along the real interval." The divisor is \(2^L - 1\), not \(2^L\) — because the largest \(L\)-bit value is \(2^L - 1\), and you want it to land exactly on \(b\).

Common mistake: dividing by \(2^L\). With \(L = 4\) on \([0, 1]\), that maps 1111 to \(15/16 = 0.9375\) and never reaches the upper bound at all. Divide by \(2^L - 1 = 15\).

Bit-flip mutation and the size of \(p_m\)

Mutation is a unary operator. Walk the string gene by gene; with probability \(p_m\) flip that bit. In binary the flip is unambiguous — the only alternative value is the complement.

The lecture's guide: \(p_m\) is small, typically between \(1/\mu\) and \(1/L\). Why? At \(p_m = 0.8\) you are flipping most bits every generation, which is indistinguishable from random search — you have thrown away everything the population learned. Mutation injects randomness sporadically, not continuously.

\[ \mathbb{E}[\text{flips}] = N L p_m, \qquad \Pr[\text{no flip anywhere}] = (1 - p_m)^{NL} \]

Read it aloud: "\(N\) strings times \(L\) genes each is \(NL\) independent coin tosses." Both formulas are just the mean and the all-tails probability of \(NL\) Bernoulli trials.

A subtlety: bit-flip mutation is not as unbiased as it looks

Every gene is chosen with the same probability \(p_m\) — but the effect is wildly unequal. If the string decodes to an integer, flipping the most significant bit of 1000 changes the value by 8; flipping the least significant changes it by 1. So mutation is heavily biased towards large phenotype jumps at the early genes.

The remedy named in the lecture is Gray coding: an alternative binary code in which numerically adjacent values differ by exactly one bit, so any single flip is always a small move in phenotype space. Worth one sentence if a question asks how to make binary mutation behave more locally.

Crossover on bit strings

  • One-point: one cut site, children take complementary halves.
  • Multi-point: \(n\) sites give \(n+1\) segments, taken alternately. Better for long strings, where a single cut is very coarse.
  • Uniform: decide gene by gene, at random, which parent contributes.

Nothing guarantees a child beats its parents. The hope is that useful partial structures occasionally combine and selection keeps the successes.

Why you need both operators — the sentence to reproduce: only crossover can combine information from two parents; only mutation can introduce new information.
Worked example 4 — the allele-frequency argument

Claim: a GA running crossover alone, with no mutation, cannot change the population-wide ratio of zeros to ones.

Argument. Start with 0s and 1s equally frequent — a ratio of \(1:1\) across the whole population. Crossover only moves existing genes between strings; it never manufactures a value that was not already present at that locus. Every child's bit is a copy of some parent's bit. So after ten generations of crossover alone, or a hundred, the ratio is still \(1:1\).

The consequence that matters. If an allele is lost from the population entirely — every individual carries a 0 at locus 7 — crossover can never recover it, and every solution requiring a 1 there is now unreachable forever. Mutation can recover it, because it manufactures values rather than shuffling them.

Exam form: "After 100 generations of crossover only, what is the ratio of 0s to 1s?" — Answer: still \(1:1\), because crossover is a redistribution, not a source. Then add the lost-allele consequence for the second mark.

Exploration vs exploitation — use the lecture's convention. This course assigns crossover = explorative (a large jump to a point "between" the parents; the lecturer's analogy is interpolation) and mutation = exploitative (a small local perturbation of an existing solution). Several standard textbooks say the opposite. Use the lecture's labels here, and if asked to justify, argue from step size: crossover makes the large jump, mutation the small local move. That argument is defensible under either labelling.

5.3 Integer representation

Each gene draws from \(K\) labels rather than two, giving \(\{1,\ldots,K\}^L\). This suits problems whose decisions are categorical: which of three colours, which of five machines, which of four routes.

Two mutation options, and when each is wrong

  • Creep: add a small random \(\pm\) step to the gene. Sensible when the labels are ordinal (small, medium, large), because neighbouring values mean similar things. Its failure mode is premature convergence: creep only ever explores locally, so the population settles into a basin it cannot step out of.
  • Random resetting: replace the gene with a uniformly random label from \(\{1,\ldots,K\}\). Correct when the labels are nominal — for colours, "red plus one" is meaningless, so creep encodes a false ordering.
Worked example 5 — graph colouring as an integer problem

Problem. Colour every region of a map so no two adjacent regions share a colour, using at most \(k\) colours.

Representation. \(c \in \{1,\ldots,k\}^L\) where \(L\) is the number of regions and \(c_u\) is the colour of region \(u\). Genotype space \(k^L\).

Objective. Minimise the number of broken edges:

\[ f(c) = \sum_{(u,v) \in E} \mathbf{1}[\,c_u = c_v\,] \]

Read the indicator as "add 1 whenever two neighbours ended up the same colour." A proper colouring scores 0 — again a CSP converted into a COP by counting violations, exactly as with N-queens.

Operators. Random resetting (colours are nominal), plus any binary-style crossover — one-point, multi-point or uniform — because unlike a permutation, any string of labels is a legal candidate. \(\mathcal F = S\) again.

The fact the lecture cites: \(k = 3\) fails on the map of the United States; \(k = 4\) always suffices for any planar map, by the four-colour theorem.

5.4 Real-valued representation

The genotype is a vector of floats, usually boxed: \(x \in [\mathrm{LB}, \mathrm{UB}]^n\). This is the natural encoding for function optimisation and for tuning continuous parameters — PID control gains are the lecture's example.

Mutation on a real vector

  • Uniform: resample the gene uniformly from its bounds. A big, undirected move.
  • Gaussian: \(x_i' = x_i + N(0, \sigma)\). Small moves are likely, large moves are rare but possible. The step size \(\sigma\) is now the critical parameter — and choosing it well is problem-dependent and changes as the search progresses.
Self-adaptive mutation. Rather than tuning \(\sigma\) by hand, put it inside the chromosome — the individual is \((x_1,\ldots,x_n,\sigma)\) — and let evolution tune it. The rule you must state: mutate \(\sigma\) first, then mutate \(x\) using the new \(\sigma\).
Be ready to justify the order. The point of self-adaptation is that a step size is judged by the quality of the offspring it produced. Mutating \(\sigma\) first means the child's \(x\) was generated by the child's own \(\sigma\), so when selection judges that child it is implicitly judging that \(\sigma\). Do it the other way round and the \(\sigma\) an individual carries had nothing to do with how it was made — selection would be scoring a number that never did any work, and no adaptation occurs.

Crossover on real vectors

Arithmetic (whole) crossover blends the parents gene by gene:

\[ z_i = \alpha x_i + (1 - \alpha) y_i, \qquad \alpha \in [0,1] \]

This is a weighted average — for \(\alpha = 0.5\), exactly the midpoint. "Simple" and "single" arithmetic crossover apply the same formula to a suffix or to one gene rather than all of them.

The limitation you must be able to prove. Because \(z_i\) is a convex combination of \(x_i\) and \(y_i\), it always lies between them. So every child lands inside the parents' bounding box, and the population's box can only shrink, generation after generation. Arithmetic crossover alone contracts the search and cannot reach a region outside the current spread.

Blend crossover (BLX-\(\alpha\)) repairs exactly that. With \(d_i = y_i - x_i\), sample uniformly from the widened interval:

\[ z_i \sim U\!\left[\, x_i - \alpha d_i,\ \; y_i + \alpha d_i \,\right] \]

The interval now overhangs both parents by \(\alpha d_i\), so children can fall outside the box and the search can re-expand. Note the two \(\alpha\)s mean different things — a weight in arithmetic crossover, an overhang fraction in BLX.

Arithmetic vs blend crossover — the bounding box, drawn

Two parents in 2-D. The blue rectangle is their bounding box. Arithmetic children sit on the segment joining them; blend children scatter into the widened box. Drag the sliders and watch which operator can escape.

Worked example 6 — arithmetic crossover, by hand

Parents: \(x = (0.3,\ 0.7)\), \(y = (0.5,\ 0.1)\), with \(\alpha = 0.5\).

\(z_1 = 0.5(0.3) + 0.5(0.5) = 0.15 + 0.25 = 0.40\)
\(z_2 = 0.5(0.7) + 0.5(0.1) = 0.35 + 0.05 = 0.40\)

So \(z = (0.40,\ 0.40)\) — and the complementary child, using \(1-\alpha\), is identical. That is the point of the example: at \(\alpha = 0.5\) whole arithmetic crossover produces two identical children at the midpoint, destroying diversity in one step rather than creating it. Either use \(\alpha \ne 0.5\), or use blend crossover.

Check both coordinates: \(0.40\) lies between 0.3 and 0.5, and between 0.1 and 0.7. Inside the box, as guaranteed.

Multi-parent recombination

Nothing in the algorithm requires exactly two parents — that constraint is inherited from biology, not from mathematics. The arithmetic-crossover formula generalises to any number of parents as a weighted average \(z = \sum_k w_k x^{(k)}\) with \(\sum_k w_k = 1\). More parents means more information combined per child, and it is one of the operators where an evolutionary algorithm can straightforwardly exceed what nature does.

6.1 The governing rule

A permutation genotype is an ordering of \(1,\ldots,L\), and its defining property is that every value appears exactly once. So:

Every permutation operator must return a permutation. That single constraint is the reason four special crossovers exist. It is also your free mark: whatever you produce, finish by checking each of \(1..L\) appears once, and say that you checked.

Two problem families dominate: N-queens (as in Module 3) and the TSP, where the string is the visiting order of cities and the objective is total tour length. TSP is NP-hard, which is precisely why a heuristic is reached for.

6.2 Mutation on a permutation

OperatorWhat it doesEffect on adjacency
SwapExchange two entries.Breaks up to 4 edges. Blunt but simple.
InsertMove one entry next to another, shifting the rest along.Breaks 3 edges; keeps most of the order intact.
ScrambleRandomly reorder a subset (often a contiguous window).Highly disruptive inside the window.
InversionReverse a contiguous segment.Breaks only the 2 boundary edges — everything inside keeps its neighbours.
The reasoning a question is really testing: for TSP the cost is a sum over edges, so the operator that preserves adjacency preserves most of the cost structure. That makes inversion the natural TSP mutation — it makes a meaningful change while destroying almost nothing. Choose the operator by asking what the objective actually depends on.

1. Order-1 crossover — inherits relative order

  1. Copy the segment from \(P_1\) into the child at the same positions.
  2. Fill the remaining positions from \(P_2\), taking \(P_2\)'s values in \(P_2\)'s order, starting immediately after the segment and wrapping around, skipping any value already present.
Worked example 7 — order-1, positions 4–7

Segment from \(P_1\) is 4 5 6 7, giving the child _ _ _ | 4 5 6 7 | _ _.

Start reading \(P_2\) from position 8 and wrap: \(1, 4, 9, 3, 7, 8, 2, 6, 5\). Discard those already in the child (\(4, 5, 6, 7\)) and you are left with \(1, 9, 3, 8, 2\).

Place them into the free positions in order, also starting at position 8 and wrapping — positions \(8, 9, 1, 2, 3\):

\[ \text{child} = \texttt{3 8 2 | 4 5 6 7 | 1 9} \]

Each of \(1..9\) appears once. ✓ One parent supplied explicit values; the other supplied relative order.

2. PMX (partially mapped crossover) — inherits positions via a mapping chain

The most commonly used permutation crossover, and the one most often botched under time pressure.

  1. Copy a segment from \(P_1\) into the child at the same positions.
  2. Look at \(P_2\)'s values in that same segment. Those already present are "partially matched" — no action. For each value \(v\) that is not present, find its home: look at the value \(w\) that \(P_1\) holds at \(v\)'s position; find where \(w\) sits in \(P_2\); place \(v\) there if free, and if not, repeat the chain with \(w\).
  3. Fill every remaining position with \(P_2\)'s value at that position.
Worked example 8 — PMX, both children

Child 1. Segment gives _ _ _ | 4 5 6 7 | _ _. \(P_2\)'s segment is \(8, 2, 6, 5\); the 6 and 5 are already present, so only 8 and 2 need placing.

  • \(2\) sits at position 5. \(P_1\) has \(5\) there. \(5\) sits at position 7 in \(P_2\) — occupied by 7. So chain on: \(7\) sits at position 3 in \(P_2\) — free. 2 goes to position 3.
  • \(8\) sits at position 4. \(P_1\) has \(4\) there. \(4\) sits at position 9 in \(P_2\) — free. 8 goes to position 9.

Fill positions 1, 2, 8 from \(P_2\): \(9, 3, 1\).

\[ \text{child}_1 = \texttt{9 3 2 | 4 5 6 7 | 1 8} \]

Child 2 (roles reversed, \(P_2\) donates 8 2 6 5). The unmatched values are now 4 and 7: \(4\) maps via \(8\) to position 8, and \(7\) maps via \(5\), then via \(2\), to position 2.

\[ \text{child}_2 = \texttt{1 7 3 | 8 2 6 5 | 4 9} \]

Always finish by confirming each of \(1..9\) appears exactly once. ✓

3. Cycle crossover — inherits absolute positions

This operator asks a different question: which genes are locked together by the two parents? Start at a position, take \(P_1\)'s value; find where \(P_2\)'s value at that position sits in \(P_1\); move there; repeat until you return to the start. That closed loop is a cycle.

Worked example 9 — the three cycles
  • Cycle 1: \(1 \to 9 \to 4 \to 8 \to 1\), i.e. positions \(\{1, 4, 8, 9\}\).
  • Cycle 2: \(2 \to 3 \to 7 \to 5 \to 2\), i.e. positions \(\{2, 3, 5, 7\}\).
  • Cycle 3: position \(\{6\}\) alone — both parents hold 6 there, so it is a fixed point.

Build offspring by taking whole cycles alternately from the two parents:

\[ \text{child}_1 = \texttt{1 3 7 4 2 6 5 8 9}, \qquad \text{child}_2 = \texttt{9 2 3 8 5 6 7 1 4} \]

Because cycles are exchanged whole, validity is automatic, and every gene keeps a position it held in one of its parents. That is the defining property: cycle crossover preserves absolute position.

4. Edge recombination — inherits edges

The first three operators manipulate gene values and positions. But for a routing problem, the cost does not depend on where a city sits in the string — it depends on which cities it is next to. Edge recombination therefore inherits adjacency directly.

  1. Build the edge table. For each city, list its neighbours in both parents. Treat the tour as a closed circuit, so the last city is adjacent to the first. Mark with \(+\) any neighbour appearing in both parents — a common edge.
  2. Construct the child one city at a time from a random start, deleting each chosen city from every list, and choosing the next by these rules in order:
    1. if a common edge (\(+\)) is available from the current city, take it;
    2. otherwise take the candidate whose own neighbour list is shortest;
    3. break ties at random;
    4. if the current city's list is empty, jump to any unused city at random.
Two things people forget: the wrap-around edge (city 9 is adjacent to city 1 in a closed tour), and rule (b) — shortest list, not longest. Taking the shortest list first is a greedy hedge: you visit the most constrained city while it still has options, so you are less likely to strand yourself and be forced into a random jump.
Worked example 10 — edge table and a full construction
CityNeighboursCityNeighbours
12, 9, 5, 465⁺, 7, 2

Run, starting at city 1:

  • From 1, candidates are \(2, 5, 4, 9\) with remaining list lengths \(3, 2, 3, 3\) → 5 is shortest.
  • From 5, the common edge \(6^+\) is available → 6.
  • From 6, candidates 7 and 2 both have two entries → tie, break at random → 7.
  • From 7, common edge \(8^+\) → 8.

  • From 3, candidates 4 and 9 each have one entry → tie → 4, then 9.
\[ \text{child} = \texttt{1 5 6 7 8 2 3 4 9} \]

A valid permutation built entirely from inherited edges. Note the two random tie-breaks: a different run would legitimately give a different child, and saying so is part of a complete answer.

Why it is called constructive: unlike the other three, it does not copy blocks — it builds the solution one element at a time under a rule, the way a deterministic constructive heuristic does.

6.4 Tree representation and genetic programming

Some objects are naturally trees rather than strings: an arithmetic expression, a logical formula, a program, a finite-state machine. Evolving trees is genetic programming, and what is being evolved is a structure, not a list of values.

A tree is built from two declared sets — and declaring them is the representation decision:

function setThe internal (non-terminal) nodes: the operators, e.g. \(\{+, -, \times, \div\}\) or \(\{\wedge, \vee, \neg, \rightarrow\}\).
terminal setThe leaves: variables and constants, e.g. \(\{x, y, 2, 3, \pi\}\).

Reading a tree is just operator precedence — the root is the operation applied last. For \(2\pi + \left((x+3) - \frac{y}{5+1}\right)\): the root is \(+\); its left subtree is \(\times\) over the leaves 2 and \(\pi\); its right subtree is \(-\), whose left subtree is \(+\) over \(x\) and 3, and whose right subtree is \(\div\) over \(y\) and a \(+\) node over 5 and 1.

Variation on trees

  • Mutation: choose a node at random and replace the subtree rooted there with a newly generated subtree — possibly just a single terminal.
  • Recombination: choose a node in each parent and exchange the two subtrees. The direct analogue of exchanging substrings.
The consequence worth stating: tree chromosomes are variable length and non-linear. Unlike every other representation in this course, two chromosomes need not be the same size — and subtree exchange changes the size of both children. (The runaway growth this causes has a name, bloat, though the lecture does not dwell on it.)

Where EAs stand — heuristics, neighbourhoods, no free lunch

0%Not started

7.1 Heuristics and metaheuristics

heuristicA rule of thumb that guides search towards good solutions without guaranteeing the best one. Usually problem-specific — "always visit the nearest unvisited city."
metaheuristicA problem-independent strategy for building heuristics — a template you instantiate. An EA is a metaheuristic: it says nothing about your problem until you supply a representation and a fitness function.

The two strands of natural inspiration behind this family: evolution (populations, selection, inheritance — GAs, GP, evolution strategies) and collective/physical behaviour (swarming, annealing — PSO, ant colony, simulated annealing).

7.2 Deterministic versus heuristic

Deterministic (exact)Heuristic
ResultGuaranteed optimal, or a proof there is noneA good solution, with no certificate of optimality
TimeBounded and analysable — but the bound may be astronomicalWhatever you allot; you choose when to stop
RepeatabilitySame input → same outputStochastic: same input → different runs
The catchConverges, but may be unaffordableWorks, but certifies nothing
The trade in one line: you give up the guarantee of optimality in order to buy back the running time. If a problem is small or has exploitable structure, do not reach for an EA — use the exact method.

7.3 Global and local optimisation — and what a neighbourhood is

A neighbourhood \(N(s)\) is the set of solutions reachable from \(s\) by one move of your chosen operator. It is defined by the operator, not by the problem.

local optimum\(s\) with \(f(s) \ge f(s')\) for all \(s' \in N(s)\). Best in its neighbourhood only.
global optimum\(s^\*\) with \(f(s^\*) \ge f(s)\) for all \(s \in \mathcal F\). Best in the entire feasible set.
The point the lecture insists on: "local optimum" is undefined until you have defined the neighbourhood. The same point can be a local optimum under swap moves and not under inversion moves — change the operator and the landscape's peaks move. So an EA does not escape local optima by magic; it uses a population plus mutation to sample outside any single neighbourhood.

7.4 No free lunch

Build the picture the way the lecture does. Put performance on the vertical axis and all possible problems along the horizontal, then plot several algorithms:

  • Random search — a flat line. Mediocre on everything, equally.
  • A special-purpose method — a tall narrow spike. Superb on the problems it was designed for, terrible elsewhere.
  • EA₁ … EA₄ — broad humps in different places, each biased towards a different kind of landscape.

The Socratic question the lecturer asks is "so which algorithm is better?" — and the answer is that the area under every curve is the same.

\[ \overline{P}(\text{algorithm}) = \frac{1}{|\mathcal{P}|}\sum_{p \in \mathcal{P}} P(\text{algorithm}, p) \quad \text{is identical for all algorithms} \]

Read it aloud: "averaged over every possible problem, all algorithms perform equally well." Any gain on one class of problems is paid for by a loss on another.

Lab 9

The no-free-lunch picture

Move the specialisation slider. As an algorithm's peak grows taller and narrower, its performance elsewhere sinks — and the area under its curve never changes. That conservation is the theorem.

What NFL does not say — this is where the marks are.
  • It does not say all algorithms are equally good on your problem. Real problems are a vanishingly small, highly structured subset of "all possible problems." On that subset, differences are enormous.
  • It does not say algorithm choice is pointless. It says the opposite: since no universal winner exists, matching the algorithm's bias to the problem's structure is the entire job.
  • It does not say EAs are useless — only that an EA's broad competence is bought by not being the best at anything in particular.
The practical conclusion the lecture draws: incorporating domain knowledge — through the representation, a tailored operator, a smarter fitness function, or a seeded initial population — is what buys performance. The N-queens paper's weak-gene targeting (Module 3) is exactly this move.
